# 交接文件 — KT89S51 模擬器

> 寫於 context 即將壓縮前。接手的人（或壓縮後的我）請先讀完這份再動手。

---

## 1. 這個專案是什麼

堃喬 **KT89S51 V4.2 主板 + KDM+ 擴充板** 的軟體模擬器。使用者把 `.asm`（主要）或 `.c` 丟進去，
模擬器編譯後逐指令執行，畫面上的虛擬板子會真的亮燈、發聲、顯示、轉馬達，並可單步／下中斷點／看波形。

- **本機版**：`啟動模擬器.bat` → `http://127.0.0.1:8051/`
- **線上版**：https://claude.ai/artifact/XeDXCphGUBabAAr4T9EqDj （目前 Version 8）
- **主要語言是組合語言**（Keil µVision A51 語法），不是 C。使用者明確更正過。

## 4. ⚠️ 工作流程（這點被使用者糾正過，務必遵守）

**改完板子版面，一定要先算成圖看過再交付。** 不要憑想像改座標。

```bash
node tools/render-board.mjs tools/board-preview.png 2400   # 看整體
node tools/render-board.mjs tools/cmp.png 890              # 與照片同尺寸，供疊圖比對
```

疊圖比對（照片 vs 我們畫的，各 50% 透明度）：
```python
from PIL import Image
a = Image.open('rot_ccw.png').convert('RGB').crop((0,0,890,423))
b = Image.open('tools/cmp.png').convert('RGB')
Image.blend(a, b, 0.5).save('overlay.png')
```

`rot_ccw.png` = `docs/螢幕擷取畫面 2026-09-17 132245.png` 逆時針轉 90°（`im.rotate(90, expand=True)`），
尺寸 890×449。**SVG 座標 = 照片像素 × 2**（`const S = 2` in board.js），所以量到什麼就填什麼。

### 🔴 這次稽核抓到的真 bug（已修）
**JP7 的四支腳原本接反了。** 原本寫成 `B2→stepper.3、A2→stepper.2、B1→stepper.1、A1→stepper.0`，
但 `stepper.js` 的 `COIL_OF_S = [3,1,2,0]` 定義 `stepper[i] = S_i`，所以 B2 被送到 A1 的線圈。
依電路圖已改成 `B2→stepper.0、B1→stepper.1、A2→stepper.2、A1→stepper.3`。

## 7. 使用者剛提出、**尚未處理**的三件事

1. **「馬達實際上是直接接上的」** — CN3 不是要你手動接的東西，馬達本來就插在上面。
   目前 CN3 畫成 `bare`（不可接線）是對的，但要確認呈現方式有沒有誤導。

2. **「電路圖上有焊接，不代表那個針本身不能接」** ← 這點目前實作是錯的。
   `headers.js` 裡沒有給 `dev:` 或 `Px.y` 訊號的腳位一律畫成灰色、不可點。
   但實際上像 LCM 的 D0–D7、JP7 馬達座、JP1 POWER 這些腳，
   **實體上都是可以再拉線出去的**。需要把「可接線」的判定放寬 —— 
   建議：除了真正的電源/地/振盪腳，其餘都允許接線；或至少允許接到對應的埠腳位。

3. **使用者建議的做法（下一步的主線）**：
   > 先標記兩塊電路板的**所有元件**（包含跟模擬無關的電阻電容），
   > 然後每個元件精準對照三種圖，一次到位。

## 8. 下一步建議的執行順序

1. **建元件清單**：把兩塊板子上每一個有絲印編號的元件（U1 U2 U3 U4 U5、Q1–Q8、
   R1–R37、RP1–RP3、C1–C17、D1–D5、DS0–DS3、JP1–JP12、CN1–CN4、SW1、PB0–PB4、Y1 Y2、B1）
   列成一張表，欄位：`編號 / 種類 / 實體座標 / 電路圖位置 / 用途 / 模擬器是否需要`。
2. 逐一在照片上量座標（沿用第 5 節的方法：加網格放大 → 讀值；金色焊點用像素分布找欄位）。
3. 更新 `headers.js` + `board.js`，每加一批就 render 一次比對。
4. 放寬「可接線」判定（第 7 點第 2 項）。
5. 把整張對照表寫進 `docs/接腳對照表.md`，並加一個測試鎖住它，避免以後改壞。
